기존 모델과 새 설치 경로 확인

배포판 폴더에서 Bash를 열거나 해당 경로를 입력하세요. ZIP으로 받았다면 같은 릴리스의 SHA-256을 먼저 확인하세요. 소스와 Python 의존성을 받는 단계에서 인터넷을 사용합니다.

지정한 Strata 체크아웃의 현재 커밋을 복사해 패치합니다. 엔진 0.1.60을 기준으로 검증했습니다. 다른 버전은 빌드와 응답 검증을 거쳐 적용하세요.

체크아웃이 없다면 검증 기준 소스 받기를 참고하세요. 새 런타임은 off로 시작합니다.

Bash

별도 엔진 빌드와 루프백 시작

86-real은 RTX 3090 예시입니다. 사용하는 GPU의 아키텍처 값을 확인하세요. 기존 프로필 JSON과 모델 파일은 그대로 두고 새 엔진만 빌드합니다.

두 모델이 GPU 메모리에 들어가지 않으면 원래 실행 명령을 확보한 다음 기존 서버를 정지하세요.

Bash

정책을 켜고 확인

모델이 로드되면 별도 Bash에서 실행하세요. 서버가 API 키를 요구하면 검증 터미널에서만 STRATA_API_KEY를 설정하세요.

  1. 초기 해제 상태에서 강제 적용을 거부하는지 확인합니다.
  2. 정책을 켜서 ‘아홉 시’와 東京 보존을 확인합니다.
  3. 한자만 쓰라는 요청을 강제로 제한하면 빈 본문이 올 수 있습니다.
Bash

복구 범위 선택

패치 서버는 계속 실행됩니다. 정책을 끈 뒤 새로운 요청에 off가 표시되는지 확인합니다.

  1. 별도 서버 터미널에서 Ctrl+C를 눌러 종료합니다.
  2. 기존 서버를 중지했었다면 원래 명령과 프로필로 시작합니다.
  3. 클라이언트 주소를 되돌리고 원래 서버의 /health에서 모델 로드 상태를 확인합니다.
